## 2. 规则整理（草案 → 数值表）

### 2.1 地图与控制区
- 六边形网格，A/B 双方各占一角的 HQ。
- **一个格子只允许一个建筑**；**单位可以多个叠在同一格**（参考-6）。
- 每个建筑有「控制半径」：普通建筑 = 1，HQ = 2（升级再 +1）。控制区 = 半径内所有六边形。
- 一个格子可以同时属于多个区域，按阵营颜色描地块边缘（参考-3）。
- **只能在自己控制区内建造**；**敌方控制区内不能放建筑，但敌人可以走进任何区域**（参考-3）。
- 建造/升级通过「点选己方建筑 → 面板 → 建造/升级/拆除」，无建筑时弹出环形造价菜单（参考-5）。

### 2.2 回合
- 双方交替行动；每回合开始结算金币收入，然后抽卡/发卡，再做行动。
- 每个单位每回合：**1 次移动 + 1 次攻击**。
- 建筑：每回合可攻击一次（HQ 指定控制区内任意一格；炮台打最近目标）。

### 2.3 单位（草案-7 + 资产名）

| 步兵 infantry | 150 | 1 | 1 | 100 | 否 | 基础单位 |
| 坦克 tank | 450 | 1 | 2 | 200 | 否 | 不可对空 |
| 导弹车 missile_launcher | 250 | 1 | 3 | 400 | 是 | 可对地对空 |
| 武装直升机 helicopter | 250 | 2 | 2 | 150 | 否 | 空袭/空中单位 |
| 战斗机 fighter | 400 | 3 | 2 | 300 | 是 | 空中单位，可越格 |

### 2.5 卡牌与操作（参考-4/6）
- **需要选地块的卡**（单位卡）：点/拖动选中卡 → 地图高亮所有合法格 → 点击格子部署。
- **不需要选地块的卡**（魔法卡：空袭、导弹袭击、维修、加成）：再次双击卡，或向上拖出一段距离即打出。
- 选中的卡要有提示；点空地/非法区域取消选中。
- 手牌在屏幕底部呈扇形铺开，可拖动换位（参考-6）。

## 9. 3渲2（toon + next pass 描边）落地说明

所有模型（建筑、兵种、装饰物）现在都走 `scripts/core/ToonMaterial.cs` 统一处理：
`toon_cel.gdshader` + `next_pass = toon_outline.gdshader`，描边色 `#3B2E16`，三段色阶 0.42 / 0.72。

三个必须注意的点（都是踩过的坑）：

1. **描边宽度要按缩放补偿。** 描边 shader 是在模型空间沿法线外推顶点，而模型被等比缩小到一格
   （缩放系数常在 0.1 左右），不补偿的话描边只有 0.0018 米，看不见。
   `ToonMaterial` 里按 `width = 0.014 / 模型缩放` 计算，并按「图集 + 缩放」缓存材质。
2. **建筑 glb 里含三个等级的网格。** 层级是 `Lv1` / `Lv2` 作为「Lv3 本体网格」的**子节点**，
   直接隐藏父网格会把子网格一起隐藏。所以先 `Reparent` 把三个网格提到同一层，再按等级筛选可见性，
   并按「当前等级」的包围盒重新缩放（否则 Lv1 会因为 Lv3 很高而缩成一小坨）。
3. **贴地要 XZ 居中。** 原先只把包围盒最小角对齐到格子中心，导致每个模型偏半格；现在改成
   中心对齐格子中心、底面贴 y=0。

等级切换已经接在 `HexMapView.SyncEntities()`：建筑等级一变化就重建视图，所以升级时能看到建筑换形态；
菜单小岛固定展示三级形态。

> 截图见 `docs/screenshots/`：`01_mainmenu` / `02_battle` / `03_mapselect` / `04_result` / `05_closeup`（近景看描边与色阶）。

## 11. 模型对齐与叠放（第 4 轮）

### 建筑居中

之前用「整体 AABB 中心」对齐格子，结果带旗杆、栏杆、炮管的建筑会被这些细长零件拉偏，主体歪出六边形。现在改成：

1. 取模型**底面顶点**（低于「最低点 + 22% 高度」的顶点）；
2. 用这些顶点的 **X 中位数 / Z 中位数** 作为落点中心（中位数对细长零件不敏感，HQ 那种带栏杆的模型也能稳稳落在基座上）；
3. Y 仍然按整体最低点贴到格子顶面；
4. 缩放按整体 AABB 宽度，保证不超出格子。

俯视图 `docs/screenshots/10_topdown.png` 可以看到建筑正好落在六边形正中。

### 建筑居中与尺寸（第 9 轮修正）

原来有两处问题，实测数据能直接看出来（`--demo-fit` 打印每个建筑的包围盒与中心偏移）：

| 建筑 | 修正前 size / 偏移 | 修正后 size / 偏移 |
|---|---|---|
| city | 1.78×1.78 / (-0.53, 0.67) | **1.20×1.20 / (0.00, 0.00)** |
| hq | 1.47×1.78 / (-0.06, 0.64) | **1.08×1.31 / (-0.01, -0.02)** |
| gunTurret | 1.78×1.76 / (-0.35, -0.42) | **1.21×1.19 / (0.00, 0.00)** |

1. **中心偏移**：之前用「底面顶点中位数」当落点，遇到带长栏杆/围栏的模型就偏了半格（0.5~0.67，格子半宽才 0.87）。
   现在改成把顶点**按高度分桶**，取「模型下半部分里水平占地最大」那一层的包围盒中心——那一层就是基座，
   细长零件不会影响结果。
2. **尺寸溢出**：之前按「最长边 = 1.78」缩放，方形底座的**对角线**会到 2.5，远大于六边形，
   所以城市那种方形建筑会顶到相邻格子。现在建筑改为按**水平对角线与 1.70 对齐**（六边形内切圆直径 1.732），
   不管建筑怎么转，底座都在格子里。兵种仍按最长边缩放，大小不变。
3. **再补一次重心微调**：只靠「底面分桶」遇到 Lv2 指挥部这种一边带长平台的模型还会偏，
   现在把底面中心和「抬高部分顶点重心」各取一半，偏移降到 ≤0.1（Lv2 从 0.44 降到 0.29，剩下的是它自己的侧翼）。

> **关于「按建筑本体算尺寸」**：试过按顶点密度把围栏/地基剔掉，但这套模型里围栏和楼体在同一张网格上，
> 实测本体尺寸 Lv1 = 11.5×9.7（整体 12.1×10.0，只小 5%）、Lv3 = 10.3×10.3（整体 16×16，小 36%）。
> 真按本体缩放，Lv3 指挥部会放大到 1.87 并压到相邻格子上，所以这个方案没有采用。

### 单位动画与朝向（第 16 轮）

兵种 glb 里其实自带动画，但**每个部位是独立片段**（`Idle_Tank_Hull`、`Idle_Wheel_L1`、`Fire_Tank_Turret`…），
而一个 `AnimationPlayer` 一次只能播一个片段。所以 `scripts/battle/UnitAnimator.cs` 的做法是：

1. 扫出模型里的所有片段，按前缀分成三组：`Idle*` / `Move*`·`Walk*` / `Fire*`·`Shoot*`·`Attack*`；
2. 给**每个片段单独建一个 AnimationPlayer**（挂在原播放器同一个父节点下，`RootNode` 保持一致，否则轨道路径会错）；
3. 同一时刻只播一组：Idle 循环、Move 循环、Attack 播一次后自动回到 Idle/Move。

各兵种的片段数（实测）：

| 兵种 | Idle | Move | Attack |
|---|---|---|---|
| 步兵 | 1 (`Idle`) | 1 (`Walk`) | 1 (`Shoot`, 1.04s) |
| 坦克 | 20 | 20 | 20 (`Fire_*`, 1.50s) |
| 导弹车 | 13 | 13 | 13 |
| 直升机 | 5 | 5 | 5 |
| 战斗机 | 5 | 5 | 5 |

**朝向**：模型正面是本地 +Z（和原来按阵营设 ±90° 的表现一致）。
- 移动：`SyncEntities` 里检测到位置变化时，先用 0.22s 补间把 `rotation_degrees:y` 转到前进方向，再走位；
- 攻击：出手前转向目标格，并 `PlayUnitAttack()` 播一次攻击动作。

验证：`--demo-unitanim` 日志
`初始 yaw=90.0` → `移动后 yaw=-90.0 期望=-90.0` → `攻击中=True` → `1.55s 后攻击中=False`；
两张间隔 0.5s 的截图做差值，只有士兵轮廓在变化（说明 Idle 在动）。截图 `24_unit_anim.png` 是开枪姿态。

> **落地回 Idle 的坑**：`PlayIdle()` 最初只播 Idle、没有 `Stop` Move，
> 结果移动结束后 Idle 和 Move 同时在播、互相覆盖，看起来像「一直还在走」。
> 现在 `PlayIdle()` 会先停 Move；同时 `SyncEntities` 会 `Kill` 掉上一条位移补间，
> 并在 `Finished` 里确认「真的到目标位置了」才切回 Idle，避免中途改目标时状态错乱。
> 实测状态：`移动中=Move` → `落地后=Idle`（`DebugUnitAnimState` 只应返回单个状态）。

#### 合并式动画（重要）

这些片段的轨道**互相重叠**（`Fire_Tank_Hull` 里也有 `Tank_Hull/Tank_Turret`、`Tank_Gun` 的轨道），
最早的「每个片段一个 AnimationPlayer 同时播」会互相抢同一属性，表现为炮塔一转就弹回 0。
现在改成 **按状态合并成一条动画**：同一条轨道（节点路径 + 属性）只保留第一次出现的版本，
每个状态只用一个 AnimationPlayer（20 条片段 → 3 个播放器），顺带把播放器数量从 60 降到 3。

#### 炮塔独立朝向（坦克）

`Tank_Turret` 从所有合并轨道里**剔除**（`IsTurretPath`），改由 `UnitAnimator.SetTurretYaw()` 手动控制：

- 移动：炮塔回正到车头；
- 攻击：车身保持当前朝向，**只转炮塔**指向目标（`HexMapView.FaceUnitTurretToward` 返回 true 时就不再整体转身）；
- 每帧在 `_Process` 里重申一次角度，杜绝被残留动画覆盖。

验证：`--demo-tankturret`，日志 `车身yaw=90.0 炮塔相对yaw=120.0 turretOnly=True`，
开火后仍是 `车身yaw=90.0 炮塔yaw=120.0`（车身不动、炮塔锁定目标）；截图 `26_tank_turret.png`。

#### 旋翼常驻旋转（直升机）

直升机的旋翼片段（`Idle/Move/Fire_MainRotor`、`TailRotor`）会被状态切换打断，
而且片段本身带缓动（一快一慢）。现在改成**不用动画、代码匀速转**：

1. 从旋翼片段里读出该节点的**转轴**（首尾关键帧的四元数差）和**平均角速度**
   （相邻关键帧角度的累加 ÷ 片段时长，再 `Clamp(4, 16) rad/s` 防止帧采样成倒转）；
2. 每帧 `Quaternion = Rest * Quaternion(axis, angle)`，角速度恒定；
3. 旋翼轨道同样从状态动画里剔除，互不干扰。

实测：主旋翼 12.7 rad/s（≈2 圈/秒），尾桨 16 rad/s；日志角度每 0.35s 增加 4.45 rad
（12.7×0.35），严格线性。截图 `rotor_cmp.png` 两帧叶片角度不同。

### 修：强行军打出时没有烧卡特效（第 69 轮）

现象：`magic_boost`（强行军）带「消耗」关键字，但打出时只有文字提示，没有烧卡动画。

原因：烧卡动画走 `AnimateCardToPile(card, fallbackIndex)`，它依赖 `_pendingPlayedRect`——
这个矩形原本是 `ApplyCardAt()` 里记录的（指向型卡走这条路）。
而**全局卡**（不需要格子）走的是 `TryPlayGlobal(card, null)` → `ResolveCardNow()` → `AnimateCardToPile(card, -1)`，
既没经过 `ApplyCardAt`，`fallbackIndex` 又是 -1，拿到的是零矩形 → 直接 `return`，特效静默跳过。

### 牌堆查看器放大后更清晰（第 67 轮）

现象：牌堆里卡少的时候（1~3 张）卡牌会被放大到接近 1.9×，字和卡图明显发糊。

原因：卡牌的尺寸/字号是按 **128×196** 排版的，放大靠 `Control.Scale` 做**画布变换**——
文字和贴图是先在原尺寸光栅化再被拉伸的，所以越放越大越糊。

修法：

1. **放大上限收到 1.3**（`Mathf.Clamp(fitW, fitH, 0.35f, 1.3f)`）——
   卡少时不再硬撑到 1.9，面板里居中显示，牺牲一点填充度换清晰度；
2. **给查看器里的卡牌套一套 MSDF 字体主题**（`PileViewer.MsdfTheme()`）：
   `SystemFont { MultichannelSignedDistanceField = true }` + `Theme.DefaultFont`，
   距离场字体在放大时按目标尺寸重建，比普通动态字体锐利；
3. 卡图本身是**缩小**显示（`KeepAspectCovered`），不受放大影响。

截图 `62_viewer_crisp.png`（消耗堆 2 张卡，1:1 看文字边缘干净）。

### 修：打出同名卡会“多消失一张”（第 64 轮）

现象：手里有两张以上同名卡（比如 3 张步兵），打出其中一张后，**另一张也跟着不见了**。

原因是第 61 轮「手牌节点复用」引入的：

1. `TryPlayCardAt` 出牌时先 `_hud.SetHandCardVisible(index, false)` 把要打出的那张藏起来（为了让飞行动画不重影）；
2. 落地后 `RefreshAll()` → `CardHandView.Refresh()` 把这批节点**复用**给剩下的卡；

修复：复用节点时强制 `card.Visible = true`（显式注释了原因，避免以后又被“优化”掉）。

### 手牌位置平滑过渡（第 61 轮）

以前 `CardHandView.Refresh()` 会把所有卡牌节点 `QueueFree()` 后重建，再 `Relayout(false)` 瞬间摆位，
所以手牌数量一变（抽牌、出牌、弃牌）整排卡就会「跳」一下。

现在改成**复用节点 + 补间动画**：

- `Refresh()` 按「卡牌 id + 第几次出现」把旧 `CardView` 和新手牌配对，
  能对上的直接复用（保留当前 `Position/Rotation/Scale`），只有真正离开手牌的才销毁；
- 复用的卡调用 `Setup(def, i, affordable)` 只更新数据与下标（`Build()` 内部会提前返回）；
- 新抽到的卡先出现在最右侧，然后一起走 `Relayout(true)` 的 0.16s Cubic 缓出补间，
  从当前位置渐变到新目标位置；
- 卡牌事件改为在触发时用 `_cards.IndexOf(card)` 解析下标，避免复用后闭包拿到旧 index。

### 修：陆军会被部署到水面上（第 57 轮）

现象：AI（或玩家）把坦克、导弹车这类陆军部署到了水面格子上。

原因：`BattleState.CanDeployCard()` 只校验了「卡是不是单位卡」「格子在自己控制区」，
**完全没看地形** —— 移动规则（`Cell.CanGroundEnter`）挡水，但部署不挡，
所以单位被放到水上后就再也动不了。

修复：部署时加地形判断

```csharp
UnitDef unitDef = GameDatabase.Unit(card.Unit);
if (unitDef != null && !unitDef.IsAir && cell.Terrain == TerrainType.Water)
{
	error = "陆军不能部署在水面上";
	return false;
}
```

因为玩家的部署高亮和 AI 的选点（`AIController.FindDeploySpot`）都用这个函数，
改一处两边同时生效；空军仍然可以停在水面格上（设计如此）。

验证：`--demo-water-deploy`，日志
`水面格 (4,2) 陆军可部署=False err=陆军不能部署在水面上`、
`空军可部署=False err=只能部署在自己的控制区内`（说明水面本身不拦空军）、
`场上站在水上的陆军数量=0`。

### 修：打不出去的卡也会先放特效（第 56 轮）

现象：目标不合法的打击卡（比如砸敌方指挥部、落在防空炮范围里、维修空格子），
特效照播、卡牌照飞，**特效放完才弹「打不出去」的提示**。

原因：早先为了「别飞到一半才发现无效」，`TryPlayCardAt` 里做了预校验，
但预校验失败时是 `return ApplyCardAt(...)`（借原逻辑弹提示）——
后来 `TryPlayGlobal` 改成了「先播特效、命中再结算」，这条路就变成「先放特效、后报错」了。

修复：把「能不能打」抽成 `BattleState.CanPlayGlobalCard(st, cardId, target, out error)`
（金币 / 未知卡 / 需要地块 / 维修目标有无己方单位 / 敌方指挥部 / 防空炮范围），三处共用：

1. `PlayGlobalCard()` 开头先调它（状态层兜底）；
2. `TryPlayCardAt()` 用它替换原来的零散判断 —— 不合法就**直接 toast + 不飞卡、不播特效**；
3. `TryPlayGlobal()` 播特效前再校验一次（防止中途状态变化）。

验证：`--demo-strike-hq`，日志

### AI 的攻击与打击卡也走特效（第 54 轮）

`AIController` 改成**异步回合**，攻击和打击卡可以交给表现层处理：

```csharp
public Func<UnitInst, HexCoord, Task> AttackHook;   // AI 攻击
public Func<string, HexCoord, Task> StrikeHook;     // AI 打击卡
public async Task<string> RunTurnAsync()            // 逐条 await，特效播完再继续
public string RunTurn() => RunTurnAsync().GetAwaiter().GetResult();  // 无钩子时同步跑（自动测试用）
```

`BattleScene.RunEnemyTurnDeferred` 改成 `async void`，给 AI 装上两个钩子：

- `PlayAiAttackAsync`：转向 → 播放攻击动作 → 攻击音效 → 伤害特效 →
  `await` 命中延迟 → `PerformAttack` → `SyncEntities`（带死亡缩放）→ 小间隔；
- `PlayAiStrikeAsync`：`PlayCardVfx(PlayerId.Enemy, …)`（敌方自己的发射井发射导弹）→
  `await` 命中 → `PlayGlobalCard` → `SyncEntities`。

钩子为空时（`--autoplay` 的 AI 对 AI）走原来的同步结算，行为完全一致、不会死锁。

验证：`--demo-enemy-turn` 截图 `50_ai_attack_vfx.png` —— 敌方坦克开火，
爆炸光效出现的同时我方步兵正在缩放消失。

### 打击卡也在爆炸瞬间结算（第 53 轮）

第 51 轮只改了「单位攻击」，这张卡（空袭/导弹袭击/维修）还是先扣血再放特效。现在统一了：

- `TryPlayGlobal` 不再立刻 `PlayGlobalCard`，而是：
  1. `float impact = PlayCardVfx(card, target)` —— 播特效并返回命中延迟
	 （空袭 `0.5 + 0.28 = 0.78s`（三发错开）、导弹 `1.1s`（发射井版）/ `0.55s`（直落兜底）、维修 `0.15s`）；
  2. 存进 `_pendingCard`，`CreateTimer(impact)` 到点后 → `ResolvePendingCard()` → `ResolveCardNow()`：
	 这时才扣血、提示战报、`SyncEntities()`（带死亡缩放）、刷新界面、`CheckGameOver`；
- 等待期间 `OnLeftClick` 直接返回（和 `_pendingAttack` 一起判断），不会重复出牌。

验证：`--demo-missile-card`，日志
`打出瞬间 敌人HP=150（应等于 150）待结算=True` → `发射井动画 Fire_Silo_Missile playing=True`
→ `命中后 敌人存活=False HP=-200`（350 伤害）；截图 `49_missile_impact.png`（爆炸瞬间敌人正在缩放消失）。

### AI 更会用打击卡（第 52 轮）

之前 AI 只是「手里第一张买得起的打击卡 + 随便找个敌人多的格子」，价值低于 120 就放弃，
所以很少真的打出空袭/导弹。

现在（`AIController`）：

1. **逐卡逐格评估**：手牌里每张打击卡都算一遍「最佳目标 + 收益」，按 **收益/费用** 选最划算的那张；
2. **价值模型**（`BestStrikeTarget(card)`）：
   - 单位：`min(剩余血量, 伤害) × 0.6`，能一击必杀再加 `对方攻击力 × 1.4`；
   - 建筑：`min(剩余血量, 伤害) × 0.5`，打掉加 120；
   - 跳过敌方指挥部（规则不允许打）；
3. **动态门槛**：金币宽裕（≥ 费用+300）时只要打出理论伤害的 35% 就用，钱紧时要求 45%；
4. **维修卡单独处理**：`TryRepairCard()` 找己方残血最多的一格修（原来是把它当打击卡用，一直报错）。

实测（`--autoplay`，双方都是 AI）：

```

回合13 Enemy:  导弹袭击：城市 -350，城市 被摧毁
回合15 Player: 维修：战斗机 +200
```

一发放到「多单位 + 建筑」的格子上，收益比原来只看单个目标高很多。

### 命中瞬间结算 + 单位死亡缩放（第 51 轮）

1. **伤害在特效应中那一刻才结算**（原来是先扣血、再放特效）：
   `OnLeftClick` 的攻击分支不再直接 `PerformAttack`，而是
   - `float impact = PlayAttackVfx(...)`（每种武器返回命中延迟：
	 步兵 0.05s / 坦克 0.09s / 直升机 0.12s / 战斗机 0.30s / 导弹车 0.45s）；
   - 把这一击存进 `_pendingAttack`，`CreateTimer(impact)` 到点后调 `ResolvePendingAttack()`：
	 这时才扣血、提示战报、清尸体、刷新界面；

   单位阵亡时先 `scale 1 → 0.01`（`Back + In`，0.3 秒）再 `QueueFree`；

### 排查：敌方生产建筑是否会给我方发牌（第 49 轮）

`AIController` 增加一个「紧张度」评分（0~1），用来决定「先修防御还是先搞经济」：

```
紧张度 = clamp( 敌方近处战力 / 己方战力 × 0.85 + 指挥部掉血比例 × 0.45 )
```

- 敌方单位按**离指挥部的距离**加权（距离 1 权重 1.0，距离 5 权重 0.2，超过 5 不计算）；
- 己方战力不足、指挥部血少 → 紧张度升高。

每个建筑候选都带一个「划算程度」权重（`UpgradeWeight`）：

| 建筑 | 权重公式 | 含义 |
|---|---|---|
| 炮台 / 防空炮 | `1.15 + 紧张度×1.9` | 越紧张越优先修炮 |
| 兵营 | `0.85 + 紧张度×1.0` | 紧张时提升出兵质量 |
| 直升机坪 | `1.0 + (1−紧张度)×1.1` | 平稳时冲战斗机 |
| 城市 | `0.55 + (1−紧张度)×1.5` | 平稳时扩经济 |
| 指挥部 | `1.25 + (1−紧张度)×0.5` | 抽牌 / 控制半径 |

决策流程：把「该补的建筑 + 所有可升级建筑」都列成候选 → 按权重排序 →
优先执行**权重最高且买得起**的那个；都买不起就攒钱攒权重最高的。
紧张度 ≥ 0.6 时**排除经济类**（城市）候选，避免"家门口着火还在盖房子"。

实测（`--autoplay --ai-log`）：

```
T5 紧张度=0.73 计划=建造炮台   金币=200 → 未执行（攒钱）
T6 紧张度=0.73 计划=建造炮台   金币=250 → 已执行
T3 紧张度=0.24 计划=升级直升机坪 Lv2
T4 紧张度=0.00 计划=升级城市 Lv2
```

### 移动到位后把这一轮动画播完（第 30 轮）

单位走到目标格后，**不会**立刻切回 Idle：

- `UnitAnimator.PlayIdle()` 会先看移动动画播到哪儿，算出「这一轮还剩多少」；
- 把切换延后到这一轮结束（`_idleDelay`，`_Process` 里倒计时），最多等 2.5 秒；
- 期间又下令移动的话，`PlayMove()` 会把等待取消。

这样像战斗机这种长循环的移动动作不会在中途被掐断（之前会在飞完一半时突然跳回悬停姿势）。
验证：`--demo-move-anim`，日志
`移动前 Idle` → 到达后 `t+0.35s Move` … `t+1.75s Move` → `t+2.10s Idle`。

> 动画切换是「这一轮播完再切」，不是交叉淡化——两个状态在各自的 AnimationPlayer 里，
> 真要淡入淡出得把三个片段合并进同一个播放器再用 `Play(name, blend)`，
> 属于较大的重构；如果之后你看到切换处仍有轻微跳变，我可以做那一步。

### 炮台低等级「只有炮管没有炮塔」（第 16 轮）

`SetBuildingLevel` 原来对 `Barrel`/`Turret`/`Flash` 这类部件一律「始终显示」，
但 reparent 之后已经看不出部件属于哪一级，于是炮台 Lv1 会出现「光秃秃一根炮管悬在那」。

修复：在 reparent **之前**把每个网格的原始父级链记进 `origChain`，判断时把链一起拼进 key：

- 链里有 `Lv1` / `Lv2` → 跟随该等级显示；
- 链为空 → 顶层网格（主体），按 `level >= 3 || showMain`；
- 链非空且不含等级 → 挂在主体下的部件，跟主体一起显示/隐藏。

验证：`--demo-turret3`，Lv1 只剩 `Lv1` 网格（`GT_Head`/`GT_Barrels`/`MG_Barrel` 全部隐藏），
Lv2 显示 `Lv2 + GT_Head + GT_Barrels`，Lv3 显示 `GunTurret + MG_Barrel`；截图 `25_turret_levels.png`。

### 防空炮 Lv1/Lv2 没有炮塔（第 17 轮）

防空炮的结构和炮台正好相反：

```
AAGun（主体 = 基座平台）
  AA_Turret（炮塔）→ AA_Barrels（炮管）→ AA_Flash_L/R
Lv1（基座 + 沙袋） / Lv2（基座 + 围墙）
```

炮塔挂在**主体**下面（链里没有 Lv1/Lv2），按上一轮的规则会跟着主体一起在低等级隐藏，
于是 Lv1/Lv2 只剩围栏和沙袋、没有炮。

修复：`buildings.json` 加 `"alwaysShowParts": true`（防空炮开启）。
打开后，名字里含 Turret/Barrel/Flash/Flame/Missile 的部件在任何等级都显示。
防空炮同时打开 `"showMainMesh": true`，因为**圆形炮座在主体网格里**——
只显示炮塔的话炮塔会悬空；两个都打开后，Lv1/Lv2 是「底座 + 炮座 + 炮塔 + 该等级的沙袋/围墙」。

同时修了一个连带问题：`DropFloatingParts`（补悬空楼层）原来对所有可见网格都做，
把炮塔网格自己的顶点也下移了（炮塔高度从 0.86 被压到 0.44）。
现在**只对 Lv1/Lv2 网格**做，部件保持原变换。

验证：`--demo-aa3` 的网格日志里，Lv1/Lv2 的 `AA_Turret`/`AA_Barrels`/`AA_Flash_*` 全部 `vis=True`；
截图 `27_aa_levels.png`（三级都有炮塔）。

### 建筑等级规则修正（第 18 轮）

看了素材目录里的《建筑的指南》，之前把等级理解错了一级：

> Lv0：初始等级。Lv1：升一级之后就**在 Lv0 的模型上添加额外部件**；Lv2 在 Lv1 上再加。
> 每一级新添的装饰放在以等级命名的子物体下。

也就是说：**模型 Lv0/Lv1/Lv2 对应游戏 Lv1/Lv2/Lv3，而且是逐级叠加**。
之前的代码把「Lv1 网格」当成游戏的第一级，等于整体错位一级，才出现「低等级没炮塔 / 楼体悬空」这些怪象。

现在的规则（`ModelUtil.SetBuildingLevel`）：

| 游戏等级 | 显示内容 |
|---|---|
| Lv1 (=模型 Lv0) | 基础模型 + 挂在它下面的部件（炮塔、炮管） |
| Lv2 (=模型 Lv1) | + `Lv1` 节点下的所有子物体 |
| Lv3 (=模型 Lv2) | + `Lv2` 节点下的所有子物体 |

尺寸按**所有网格**（含当前等级隐藏的）统一量，升级时整栋楼的缩放保持一致，不会忽大忽小。

之前为了绕过错位加的三样东西全部删除：`showMainMesh` / `alwaysShowParts` / `DropFloatingParts`
（"楼体悬空"其实是 Lv1 装饰本来就该叠在底座上，不需要往下拉）。

各建筑三级外观已与 `gameAsset/textures/buildingsPreview/*.png` 逐个对照通过：
炮台（沙袋→红梁→天线灯柱）、防空炮（空场地→沙袋岗楼→围墙）、
指挥部（单层→二层→雷达塔楼）、兵营（营房→水塔→瞭望塔）、城市（2 层→4 层→更高）。
调试参数：`--demo-levels=<defId>` 三级并排、`--demo-buildtree=<defId>` 打印节点树。


### 单位叠在建筑格上

草案允许一格多个单位，所以单位可以部署到有建筑的格子上，这时会和建筑模型穿模。现在的处理：**单位站到建筑的「屋顶高度」**（顶点 Y 的 90 分位，忽略旗杆/天线），并且是**补间渐变**上去的：

- 新建单位时从格子顶面用 0.55s 缓和曲线升到屋顶；
- 已有单位因建造/升级导致高度变化时，`SyncEntities` 里按距离算 0.28~0.6s 的补间（不是瞬移）。

### 同格多单位：横向散开 + 每层再错开 + 略微抬高

一格里有多个单位时，按它们在格子里的**先后顺序**把它们横向散到格子内圈：

- 1 个：站正中；
- 2 个：左右分开；
- 3 个及以上：沿圆均匀分布（6 个正好对应六边形的 6 个方位）。

**每一层再额外往外错开 0.09 米**（`UnitStackStagger`，上限 0.76 米，不会推出格子），
所以叠在一起时每个单位都露得出来，不会糊成一坨；每个单位另外只抬高 **0.08 米/层**（`UnitStackLift`）。
底层单位死了或移走，其它单位会**补间挪到新位置**，不会瞬移。截图：`13_stack.png`（步兵×2 + 坦克 同格）。

截图：`09_stack.png`（叠放近景）、`10_topdown.png`（俯视核对居中）。

调试参数：`--topdown`、`--demo-stack`。

## 12. 按钮动效（第 6 轮，参考 `按钮UI动画参考.mp4`）

视频里的按钮是「果冻感」：悬停放大微倾、按下压扁、松开回弹过冲。为此写了 `scripts/ui/ButtonJuice.cs`，
统一挂在**所有** UI 按钮上（主菜单、设置、总览、选图、难度、战斗 HUD 的回合结束/建造/升级/拆除、结算画面）。

| 状态 | 效果 |
|---|---|
| 悬停 | 缩放到 **1.07**、**保持水平（不倾斜）**、`ZIndex` 提到 10，0.14s Back-Out |
| 按下 | **1.06 × 0.90** 压扁，0.07s，`ZIndex` 提到 20 |
| 松手 | **一条时间轴**走完：0.07s 弹到 1.10 并甩出 ±1.4°，再用 0.24s 的 Back 缓动把「缩放 + 倾斜」一起收回原位 |

> 松手这段特意做成**单个 Tween + `TweenMethod`**：之前是「弹一下」「摆一下」「落回去」三个独立补间，
> 后一个会 `Kill` 前一个，倾斜刚甩到一半就被强制归零，看起来又抖又僵。现在一条时间轴走到底，中间不会被打断。

实现要点：只动 `Scale` / `Rotation`（`PivotOffset` 取控件中心并在 `Resized` 时更新），
这两个属性不会被 `Container` 的布局覆盖，所以放在任何 HBox/VBox/自定义布局里都安全。

验证：`--demo-button` 会模拟悬停第一个按钮、按下再松开第二个按钮，日志实测：
`hover scale=(1.07,1.07) rot=0.0deg`（悬停水平）、`press scale=(1.06,0.9)`（压扁），
松手后连续采样旋转：`1.34° → 1.09° → 0.32° → -0.05° → -0.14° → -0.01° → 0.00°`，
一条平滑的「甩出去—回正—轻微过冲」曲线，没有跳变。

### 地块描边与描边粗细（第 5 轮）

- **地块描边**：每块六边形上方 0.004 米叠一圈 0.92~1.0 半径的深色带（`#3B2E16`，不透明、无光照），
  相邻两格各出一半，合起来就是约 0.12 米宽的格子分隔线；主菜单小岛用的是同一套。
- **模型描边加粗**：`ToonMaterial.WorldOutlineWidth` 从 0.014 提到 **0.09**，
  并打开描边 shader 的 `screen_uniform`（参考距离 21 米），这样推远拉近时屏幕上的粗细基本不变，
  不会出现「拉近了描边糊成一片、推远了看不见」。
- 控制区彩色圈改成 0.80~0.93 半径、贴在深色描边内侧，并开深度测试（不再盖住单位）。

## 13. 战斗视角操作（第 7 轮）

| 操作 | 效果 |
|---|---|
| **右键拖动** | 左右拖动**旋转视角**（0.30°/px），上下拖动**调整俯角**（0.14°/px，限制 28°~82°） |
| **左 Ctrl** | **复位到开局视角**（0.35s 平滑过渡，取景距离/俯角/朝向全部还原），并提示「视角已复位」 |
| 右键单击（没拖动） | 取消当前选择（保留原来的手感） |
| 中键拖动 | 平移画面 |
| 滚轮 | 缩放（6~34 米） |
| Q / E | 每次旋转 22.5° |
| Esc | 取消选择 |
| 空格 | 结束回合 |

实现：`CameraRig.SaveInitialView()` 在 `BattleScene._Ready` 里取完景后调用，记下 `focus / distance / yaw / pitch`；
`ResetView()` 用 `Tween.TweenMethod` 插值，yaw 走最短路径（`Mathf.Wrap(target - from, -180, 180)`），不会绕远路。

验证：`--demo-orbit` 会模拟右键拖动 260px 再按左 Ctrl，日志打印相机世界坐标：
`moved=22.28` → 转过去了；`afterReset ... backToStart=0.00` → 精确回到原位。

### 摄像机手感设置（第 7 轮补充）

设置面板新增第三个标签页 **「摄像机」**，三个倍率滑块（0.3× ~ 3.0×，默认 1.00×）：

| 项 | 设置键 | 作用 |
|---|---|---|
| 平移速度 | `camera/pan` | 中键拖动平移的灵敏度 |
| 旋转速度 | `camera/rotate` | 右键拖动旋转、Q/E 旋转、俯角调整的灵敏度 |

`CameraRig.LoadSettings()` 在战斗开始时读取（`user://settings.cfg`），三个倍率分别乘进
`Pan()` / `Rotate()`+`Tilt()` / `Zoom()`。

同一轮修的问题：**中键平移的纵向方向原来是反的**（`forward * -screenDelta.Y`），
现在改成 `forward * screenDelta.Y`，拖动时地图跟着光标走。
另外把未选中标签页的文字颜色从 `#A89566` 加深到 `#6B5836`，否则在沙色底上看不清。

验证：`--demo-pan` 中键向下拖 200px，日志 `focus` 从 `(9.05,0,6)` 变成 `(2.23,0,-3.73)`
