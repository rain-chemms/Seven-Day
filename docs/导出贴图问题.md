# 导出后 3D 模型贴图丢失 — 排查与修复

## 现象

导出到 `E:\游戏测试\SD\` 后，所有 3D 模型都没有贴图（纯色块）。

## 根因

`scripts/core/ToonMaterial.cs` 的 `FindAtlas()` 原来在**运行时扫目录**找图集：

```csharp
string dir = modelPath.GetBaseDir();
string[] files = DirAccess.GetFilesAt(dir);      // 编辑器里能列出 *_atlas.png
foreach (string f in files)
	if (f.EndsWith("_atlas.png")) return dir + "/" + f;
```

导出包里：

- 源 `.png` 会被导入产物 **`.ctex`** 取代；
- `.import` 文件被剥离；
- PCK 内的目录扫描拿不到 `xxx_atlas.png` 这个名字（或拿不到文件）。

于是 `atlas == null` → 3渲2 材质没有 `albedo_tex` → 模型变成无贴图纯色块。

编辑器里永远正常，只有导出后复现，非常符合这个原因。

## 修复

改成按**命名约定**逐一尝试，用 `ResourceLoader.Exists` 走导入重映射（对导出包有效）；
编辑器里再保留目录扫描兜底。

```csharp
string dir = modelPath.GetBaseDir();
string baseName = modelPath.GetFile().GetBaseName();   // infantry

string[] candidates =
{
	$"{dir}/{baseName}_{baseName}_atlas.png",   // 实际命名：infantry_infantry_atlas.png
	$"{dir}/{baseName}_atlas.png",
	$"{dir}/{baseName}_Atlas.png",
};

foreach (string path in candidates)
	if (ResourceLoader.Exists(path))
		return path;

// 仅编辑器兜底
if (!OS.HasFeature("template"))
{
	foreach (string f in DirAccess.GetFilesAt(dir))
		if (f.EndsWith("_atlas.png")) return dir + "/" + f;
}

return null;
```

项目里模型图集的命名统一为 `<模型>_<模型>_atlas.png`：

```
militaries/infantry/infantry_infantry_atlas.png
militaries/tank/tank_tank_atlas.png
buildings/hq/hq_hq_atlas.png
decorates/barrel/barrel_barrel_atlas.png
```

`hexTile` 例外（`hexTile_grass.png` 等），它是直接拼路径加载的，不受影响。

## 导出配置检查（export_presets.cfg）

| 项目 | 原值 | 结论 |
|---|---|---|
| `export_filter` | `all_resources` | ✅ 贴图 / 模型 / 着色器都会打包 |
| `binary_format/embed_pck` | `true` | ✅ 资源嵌进 exe，不存在 pck 丢失 |
| `exclude_filter` | `"宣传片/*, 设计草案/*"` | ⚠️ 逗号后有空格，第二个模式实际不生效 |
| `include_filter` | 空 | ⚠️ 非资源文件（json）建议显式包含 |
| `addons/godot_mcp` | 未排除 | ⚠️ 开发用 MCP 插件被打进包，后台线程会干扰 CLI 导出 |
| `texture_format/s3tc_bptc` | `true` | ✅ 桌面 VRAM 压缩正常 |

已改为：

```
export_filter="all_resources"
include_filter="*.json"
exclude_filter="宣传片/*,设计草案/*,build_export/*,addons/godot_mcp/*"
```

## 重新导出

命令行导出在本机被两件事卡住：

1. Godot 编辑器正开着这个项目（`-e res://scenes/mainMenu.tscn`），
   `dotnet publish` 与编辑器构建锁冲突，导出停在 `dotnet_publish_project`；
2. `godot_mcp` 插件的后台线程在导出开始时反复警告、拖慢打包。

**做法**：关掉编辑器 → 编辑器里「项目 → 导出 → Windows Desktop → 导出项目」，
覆盖 `E:\游戏测试\SD\Seven-Day.exe`，再进战斗确认模型贴图恢复。
