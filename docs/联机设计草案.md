# 局域网联机设计草案（主机权威 + 动作同步）

> 目标：2 人对战，同一局域网；先跑通“能连上 → 能同步开局 → 能同步出牌/移动/攻击/出兵/建造/结束回合 → 能结算”，
> 重连、观战、多房间留到后续版本。

---

## 1. 总体方案

**主机权威 + 动作同步（Host-Authoritative Action Sync）**

```
客户端输入 → 打包「意图 Intent」→ 发给主机
主机：校验（是否轮到你 / 动作合法）→ 在主机状态上执行 → 广播「已确认 Intent」
所有端：按 Intent 在本地状态上执行同一动作 → 刷新表现
```

- 只有主机持有“最终解释权”，客户端不做本地预测（回合制，局域网 RTT 通常 <5ms，等待可接受）。
- 传输内容只有“动作”，状态由各端各自演算，流量极小（一条 intent 几十字节）。

---

## 2. 视角镜像（关键设计）

每个客户端都把**自己**当作 `PlayerId.Player`，对手当作 `PlayerId.Enemy`：

| | 主机本地 | 客户端本地 |
|---|---|---|
| 主机方 | Player | Enemy |
| 客户端方 | Enemy | Player |

好处：

- 手牌 / 金币 / 结束回合 / 相机等现有 UI 全部按 `_state.Player` 写的，**不需要改 HUD**；
- 每个玩家的手牌天然是自己的，天然隐藏对手手牌（对手是 Enemy，UI 只显示其金币）。

代价：两边的状态是“镜像”的，因此：

- 开局时主机 `BeginTurn(Player)`，客户端 `BeginTurn(Enemy)`；
- Intent 里带 `actor`（0=主机方，1=客户端方），各端按自己的视角映射为 Player/Enemy；
- Intent 只带**坐标 + 手牌序号**，不带实例 id（id 在两边分配顺序不同）。

---

## 3. 确定性

两边必须“同一动作得到同一结果”，需要：

1. **随机数按阵营分离并给种子**
   `BattleState` 增加 `Random RngOf(PlayerId)`，洗牌/洗回用它；
   种子由主机生成（`seedHost` / `seedClient`），发给客户端时交换：
   - 主机：Player=seedHost，Enemy=seedClient
   - 客户端：Player=seedClient，Enemy=seedHost
2. **卡组与起始等级随开局包一起下发**（主机当前卡组/基地等级，客户端用地图默认）
3. 逻辑不用 float、不依赖 `Dictionary` 迭代顺序（现有代码已基本满足）

> 回合制 + 动作同步下，只要“输入序列 + 种子”一致，结果就一致；
> 若出现分歧，主机可每回合附带一个状态哈希（`turn/gold/hp`）供校验，v1 先不做。

---

## 4. 消息协议

所有消息用 JSON 字符串 + `[Rpc]` 传输（`TransferMode.Reliable`）。

### 4.1 握手

| 消息 | 方向 | 内容 |
|---|---|---|
| `hello` | 客户端 → 主机 | 客户端就绪（BattleScene 的 NetBattle 节点已存在） |
| `start` | 主机 → 客户端 | `NetBattleConfig`：地图 id、难度、双方卡组、双方基地等级、双方种子 |

客户端收到 `start` 后自己 `BattleState.Create(...)`，再回 `ready`；主机收到 `ready` 才开始放行输入。

### 4.2 Intent

```json
{ "t": "deploy", "a": 0, "hand": 2, "q": 3, "r": 4 }
```

| 字段 | 含义 |
|---|---|
| `t` | 动作类型 |
| `a` | 发起方：0=主机，1=客户端 |
| `hand` | 手牌序号（deploy） |
| `q,r` | 目标坐标（deploy/move/attack/build） |
| `q2,r2` | 第二坐标（move 的起点、attack 的攻击者） |
| `card` | 卡 id（spawn） |
| `id` | 建筑定义 id（build） |

动作类型：

| t | 说明 | 参数 |
|---|---|---|
| `deploy` | 打出手牌（单位/打击卡） | hand, q, r |
| `move` | 移动单位 | q2,r2 → q,r |
| `attack` | 单位攻击 | q2,r2 → q,r |
| `spawn` | 建筑出兵 | q,r（建筑坐标）, card |
| `build` | 建造 | q,r, id |
| `upgrade` / `repair` / `demolish` | 建筑操作 | q,r |
| `end` | 结束回合 | — |
| `surrender` | 投降 | a |

### 4.3 应用与确认

- 主机收到客户端 intent：校验 `a==1 且轮到客户端` → 应用 → 广播 `applied(intent)`；
- 主机自己的 intent：应用 → 广播；
- 客户端收到 `applied`：按 `a` 映射到自己视角执行；
- 每条 intent 带 `seq`（主机递增），各端记录 `lastSeq` 去重（防止重复执行）。

## 5. 回合流程

```
主机 BeginTurn(Player)       客户端 BeginTurn(Enemy)      ← 状态镜像
	 │                            │
主机行动 ──intent──▶ 主机校验/执行 ──applied──▶ 客户端执行（作为 Player）
	 │
主机 end ──▶ EndTurn()（Player→Enemy）  =  客户端 EndTurn()（Enemy→Player）
	 │                                                        │
	 ▼                                                        ▼
客户端行动（主机视角是 Enemy）：客户端发 intent → 主机执行（作为 Enemy）→ 广播
```

- 联机模式下**不启动 AI**（`RunEnemyTurnDeferred` 直接跳过）；
- 非本地回合时：屏蔽出牌/移动/攻击/出兵/建造/结束回合，HUD 的「回合结束」按钮置灰；
- 投降：发 `surrender`，双方都把该方判负 → 走正常失败结算面板。

## 6. 界面流程

```
主菜单 → 局域网对战 → 联机大厅（新场景 scenes/lanLobby.tscn）
   ├─ 创建房间：端口（默认 7777）→ 等待对手连接 → 进入战斗（主机）
   └─ 加入房间：输入主机 IP（默认 127.0.0.1）→ 连接 → 收到 start → 进入战斗（客户端）
```

- 主机使用**当前 Session**（地图 / 难度 / 卡组 / 基地等级）；客户端沿用主机配置；
- 大厅显示：本机 IP、端口、连接状态、对手信息；
- 断线：任意一方掉线 → 提示并返回主菜单（v1 不做重连）。

|---|---|
| `scripts/net/NetIntent.cs` | Intent 枚举 + DTO + JSON 编解码 |
| `scripts/net/NetBattleConfig.cs` | 开局配置（地图/卡组/等级/种子）DTO |
| `scripts/net/LanSession.cs` | ENet 主机/客户端连接、状态、本机 IP、事件 |

| `scripts/battle/BattleScene.Net.cs` | 战斗场景的联机部分：侧别映射、执行器、输入拦截 |
| `scripts/ui/LanLobby.cs` + `scenes/lanLobby.tscn` | 联机大厅 |
| `scripts/battle/BattleState.cs` | 新增：按阵营的随机数、`Create` 支持自定义卡组/等级/种子 |

### 执行器（本地与远端共用）

`NetApplyIntent(intent)`：

1. `PlayerId side = ActorToSide(intent.a);`
2. 按 `t` 调用 `BattleState` 现成 API：
   `PlayUnitCard / PlayGlobalCard / TryMove / PerformAttack / TrySpawnFromBuilding / TryBuild / TryUpgrade / TryRepair / Demolish / EndTurn`
3. 统一收尾：`SyncEntities → RefreshZones → RefreshAll → CheckGameOver`
4. 表现：格子闪一下 + 播对应音效（不做飞牌/弹道特效，v1 从简）

> 这样本地操作和远端操作走**同一段执行代码**，天然避免“两边算法不一致”。

## 8. 风险与限制（v1 明确不做）

- ❌ 重连 / 主机迁移 / 观战 / 多房间列表（大厅只支持手输 IP）
- ❌ 客户端本地预测（所有动作等主机确认，回合制下体验可接受）
- ✅ 动画：联机模式下两端都播完整动画（见第 11 节）
- ❌ 反作弊（局域网互信，主机只做规则校验）
- ✅ 自定义卡组：双方各自使用本机保存的卡组与基地等级（见第 12 节）
- ⚠️ 版本不一致（一方旧版）会导致协议解析失败，需要提示“版本不一致”

---

## 9. 实施顺序

1. `BattleState`：按阵营 RNG + `Create` 扩展参数（不影响单机）
2. `scripts/net/*`：连接、握手、intent 编解码与 RPC
3. 大厅场景 + 主菜单入口
4. `BattleScene.Net.cs`：镜像初始化、执行器、输入拦截、回合控制
5. 联调脚本：`--lan-host` / `--lan-join <ip>` 双实例自动走一遍“部署 → 移动 → 攻击 → 结束回合 → 投降”
6. 单机回归（AI 对局、出兵、结算、投降）确认未受影响

## 11. 联机动画（两端执行路径一致）

原则：**状态变更与表现分离**。

```
ExecuteNetIntent(intent):
  1. 抓取表现所需信息（发起单位 / 卡牌定义 / 手牌矩形 / 弃牌位置）
  2. 状态变更：调用与单机同一批 BattleState API（两端完全相同）
  3. _map.SyncEntities()  → 移动补间、阵亡粒子、升级换模型
  4. PlayIntentVisuals()  → 只播表现，不参与任何状态计算
```

- 出牌：手牌飞向落点（自己）/ 屏幕上方飞向落点（对手），落点闪绿 + 出牌音效；
- 移动：`SyncEntities` 的位移补间 + 移动音效 + 落点闪绿；
- 攻击：转向目标、播放攻击动作、弹道特效、目标格红闪、命中单位/建筑抖动；
- 出兵：建筑抖动 + 出牌音效 + 闪绿；
- 建造：闪绿 + 建筑弹出；升级：换模型 + 抖动 + 升级音效；维修：绿色回血特效；
- 拆除/阵亡：`SyncEntities` 触发死亡粒子 + 缩放消失；
- 结束回合：防御建筑开火动画、收入飘字、洗牌提示、弃牌飞行动画、BGM 强度切换。

因为动画只读取“已经发生的状态”，两端即使帧率/动画时长不同也不会影响同步。

## 12. 双方各自的卡组

握手改成三段：

```
主机 → 客户端：offer（地图 / 难度）
客户端 → 主机：hello（自己的卡组 + 基地等级）
主机 → 客户端：start（最终配置：双方卡组/等级/种子）
```

- 主机侧：`DeckHost = Session.EffectiveDeck(map)`，`HqHost = Session.StartHqLevel`；
- 客户端侧：`DeckClient = 客户端上报的卡组`（主机校验每张卡存在且 ≥7 张，否则回落地图默认），`HqClient = 客户端上报等级`（1~3）；
- 客户端进战斗前会把 `Session.MapId / Difficulty` 设成主机的，保证同一张地图；
- 镜像初始化时：主机 `Player=DeckHost / Enemy=DeckClient`；客户端 `Player=DeckClient / Enemy=DeckHost`。

实测（主机默认 11 张、客户端 8 张坦克流）：

```
[Net] 已发送我方配置：8 张卡 / 基地 Lv1
[Deck] 本局使用 11 张：unit_infantry,...
[Deck] 本局使用 8 张：unit_tank,unit_tank,...
[Lan] 最终 host=True  棋盘哈希=FBA3DD44
[Lan] 最终 host=False 棋盘哈希=FBA3DD44
```
